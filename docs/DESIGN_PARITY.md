# 设计稿与客户端：能否 1:1？

## 直接结论

**不能保证**「Figma 里整张客户端界面」与「Electron / 浏览器里跑起来的界面」在**每一个像素**上都**完全一致**。

原因包括：浏览器与 Figma 的**字体渲染**不同、**亚像素**取舍不同、Ant Design **组件内部留白与状态样式**由库实现而非你手写的绝对坐标；以及缩放、系统 DPI 等。

## 当前流程分别能保证什么

| 对象 | 与 Figma 的关系 |
|------|-----------------|
| **`npm run figma:export` 得到的 PNG** | 由 **Figma 服务端渲染**，与画布导出 **一致**（这是「整页像素级」唯一严格 1:1 的载体）。 |
| **`figmaShellLayout.ts`（`figma:layout`）** | 从节点树读取 **壳层几何与大面积填充色**（侧栏宽、顶栏高、壳/内容区/侧栏/顶栏背景等），与稿在 **数值上对齐**，仍可能因组件内边距与 1px 边框表现有细微差。 |
| **`designTokens.ts`** | 代码侧 **主题色、圆角、分割线色** 等与 **Ant Design / Figma 套件** 对齐的**单一来源**，改稿时先改 Figma Variables 再改这里，减少漂移。 |
| **业务页面里的表格、表单、弹窗** | 依赖 **Ant Design 实现 + 手写布局**，需 **对照稿逐项调**，没有自动 1:1。 |

## 如何把「一致」做到可验收

1. 改壳或主色后跑 **`npm run figma:sync`**，再开 **`/design/figma`** 与真实客户端 **同屏对比**（壳尺寸与主色块应对齐）。  
2. 需要 **严格像素**的局部（如营销图、插图）：用 **SVG/PNG 资源**，不要指望纯 CSS 与 Figma 矢量导出逐点相同。  
3. 把「通过」定义成：**壳层量与 token 与稿一致 + 关键页面视觉走查无功能性偏差**，而不是无限放大到每个字重亚像素。

## 若必须再收紧

- 在 Figma 与代码中 **共用同一套 Design Tokens**（变量名与值对齐）。  
- 对关键路由做 **截图回归**（Playwright 等）与基准图对比（维护成本更高）。

更多自动化步骤见 **`docs/FIGMA_TO_APP_PIPELINE.md`**。
